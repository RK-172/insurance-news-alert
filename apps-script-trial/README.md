# Google Apps Script 시험 운영

기존 GitHub 알림을 유지하면서 Google에서 수집만 시험합니다. 텔레그램·이메일을 보내지 않으며 토큰·GitHub 로그인·유료 API를 사용하지 않습니다. 국회 입법은 포함하지 않습니다.

## 설치 — 코드 수정 없이 한 번 붙여넣기

1. [Code.gs 원본](https://raw.githubusercontent.com/RK-172/insurance-news-alert/main/apps-script-trial/Code.gs)을 열어 전체 선택(Ctrl+A), 복사(Ctrl+C)합니다.
2. [Google Apps Script 새 프로젝트](https://script.google.com/home/start)를 개인 Google 계정으로 엽니다. 새 프로젝트의 `Code.gs`에 기본으로 들어 있는 코드를 모두 지운 뒤 복사한 코드를 붙여넣습니다. 저장(Ctrl+S)하고 프로젝트 이름을 `보험정책 모니터 시험`으로 정합니다.
3. 상단 함수 선택에서 `setupTrial`을 선택한 뒤 **실행**을 누릅니다. 본인 계정의 Google 권한 승인 절차를 완료합니다. 별도의 배포 버튼, 결제수단, API 키는 필요하지 않습니다. 회사 계정은 관리자 정책으로 제한될 수 있습니다.
4. 하단 실행 로그에 나온 **기록표 주소**를 엽니다. `요약`의 성공/실패가 7 / 0인지 확인합니다. 코드 붙여넣기나 승인 중 오류가 나면 그 문구를 알려주세요. 비밀번호·토큰은 공유하지 않습니다.

이후 5분 타이머가 자동 등록됩니다. 타이머 설정 화면을 따로 만질 필요가 없습니다. 초기 설정을 다시 실행해도 중복 타이머를 만들거나 기준 목록을 지우지 않습니다.

## 운영 방식

- 자동 수집은 한국시간 06:00~21:00입니다. 야간에는 타이머 함수가 호출되더라도 외부 요청과 시트 기록 전에 바로 종료합니다.
- setupTrial의 최초 시험, runTrialNow의 수동 시험은 시각과 관계없이 실행할 수 있습니다.
- 첫 성공 시 각 게시판 최신 1페이지를 기준 목록으로 저장합니다. 과거 자료를 신규로 기록하지 않습니다.
- 이후 신규 게시물을 기록합니다. 시험은 제목 키워드로 자료를 배제하지 않으며, 제목 키워드 일치 여부는 참고 열에만 표시합니다. 첨부파일과 상세 본문 분석은 없습니다.
- 공식 사이트 접속 또는 파싱 실패는 '0건 정상'이 아니라 실패로 기록합니다. Google의 네트워크에서 접속이 가능한지는 실제 계정에서 첫 실행 후 확인해야 합니다.
- 각 게시판 최근 200개 ID를 중복 방지에 보관합니다. 점검 공백에 10건 이상 새로 등록되어 첫 페이지에서 사라진 자료는 이 시험에서 놓칠 수 있습니다. 첫 단계는 실행 주기·접속 검증용이며 운영용 완성본이 아닙니다.

## 기록표 읽는 법

- **요약:** 최근 점검 결과와 기록표 주소
- **실행기록:** 자동 시작 시각, 이전 자동 실행과의 간격, 조회·기록 소요 시간, 성공·실패 수. 수동 시험과 자동 시험은 구분됩니다. 소요 시간은 마지막 요약 기록 등 일부 마무리 작업 전까지입니다.
- **기관별점검:** 7개 게시판별 HTTP 상태와 식별 건수
- **신규자료:** Google에서 처음 확인한 시각과 제목·원문. GitHub가 이후 발송한 경우 다음 시험 실행에서 GitHub 발송 시각도 갱신합니다. 최근 300개 신규 기록만 재대조합니다.
- **GitHub비교:** Google 점검 당시 GitHub의 마지막 수집 시각과 경과 시간. 공개 raw 파일을 읽으므로 캐시·반영 지연 가능성이 있습니다.

`GitHub발송-Google발견(분)`이 양수이면 Google이 그 시간만큼 먼저 발견한 것입니다. 음수이면 GitHub가 먼저 발송했습니다. 두 시스템의 '관측 시각' 비교이며, 기관의 실제 게시 시각이나 검색 정확도 전체를 검증하는 수치는 아닙니다. GitHub에 필터 제외·기준목록으로 남은 자료는 발송 시각이 없습니다.

## 1~2일 뒤 확인

실행기록에서 '자동'·'주간' 행의 간격이 대체로 5분 부근인지 확인합니다. Google도 정시 실행을 보장하지 않으므로 실제 관측 후 판단합니다. 우선 GitHub 알림을 유지하고 시험 결과가 검증된 다음 전환합니다.

기록표 URL을 알려주셔도 연결된 접근 권한이 없으면 제가 직접 읽을 수 없을 수 있습니다. 그 경우 실행기록의 최근 행을 복사해 알려주시면 비교할 수 있습니다. 공개 공유로 전환할 필요는 없습니다.

## 중지·비용

Apps Script에서 `stopTrial`을 한 번 실행하면 이 시험의 타이머만 제거합니다. GitHub와 다른 Google 타이머에는 영향을 주지 않습니다. 기록표는 보존됩니다. 다시 시작하려면 `setupTrial`을 실행합니다.

개인 Google 계정의 기본 한도 안에서 실행하는 구성입니다. 일반 개인 계정의 예약 실행 총 한도는 하루 90분, URL 요청은 하루 20,000회입니다. 다른 Apps Script 작업과 합산되며, 지연·접속 오류로 실행시간이 늘면 한도에 도달할 수 있습니다. 유료 Google Cloud 서비스는 연결하지 않습니다.

## 검증 범위

2026-11-06: 7개 실제 목록 페이지에서 각 10개 게시물 ID를 독립적인 HTML 파서 결과와 대조했습니다. 로컬 Google 서비스 모의 환경에서 초기 설정·중복 방지·야간 경계·오류 기록·GitHub 발송 시각 갱신 등을 포함한 16개 테스트를 통과했습니다. Google 서버에서의 권한·접속·실행 주기는 사용자 계정에서 별도로 확인해야 합니다.
